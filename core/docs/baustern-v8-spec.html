6техзаданий на переработку: палитра, логотип, motion v8, контент в сценах, разделы, интро-клип

Ключевой вывод по дизайну: проблема «однообразно и пусто» — не в картинках, а в архитектуре страницы. Сейчас 7 сцен фильма несут по одному заголовку, а вся информация лежит в семи «листах» (.w-sheet) на всю высоту экрана после каждой сцены. Клиент видит пустую анимацию, потом простыню. Раздел 3.4 переносит факты внутрь сцен и оставляет только три листа, которым нужна настоящая UI (калькулятор, галерея, форма). Раздел 3.3 меняет модель прокрутки: камера едет сама, застрять посередине больше нельзя.

Важное открытие вне брифа. Домен www.baustern.ch сейчас отдаёт другой сайт — Next.js-приложение на Vercel («Bauunternehmen Zürich · Renovation & Sanitär — BauStern», Plausible-аналитика). Сборка, которую мы дорабатываем, живёт на Netlify (бейдж «Powered by Netlify» на ваших скриншотах). Прежде чем вкладывать недели в v8, нужно решение, какой из двух сайтов — продакшн (см. раздел 4).

1.2 Узкие места, найденные при разборе

  • Точка приземления = граница комнаты. Все переходы (точки слева, мини-план, кнопка «Rundgang», onLeaveBack) целились в верх .w-room. Там прогресс = 0: кадр предыдущей сцены, текст скрыт, snap держит на месте. Отсюда баги #1, #9, #10.
  • Односторонний прелоад. afterArrive(i) грузил только диапазон вперёд; окно памяти уже хранило «назад», но кадры туда никогда не запрашивались → при прокрутке вверх nearest() показывал застывший кадр.
  • Интро начиналось с последнего кадра. frame = S[0].f (63) рисовался поверх постера (кадр 0), потом клип прыгал на 0. Плюс старт по таймеру 3 с на неполном кэше → шаг 150–200 мс между кадрами.
  • Нет «ремонта» сцены 0. У комнаты 0 не было обработчика возврата: после прокрутки вверх страница оставалась в состоянии «сцена 1, is-driving».
  • Навигация без подложки над фильмом. При scrollY ≤ 40 nav белая и без затемнения — над светлыми кадрами (Bad, Küche) логотип и ссылки исчезают. На вашем скриншоте с ванной именно это: шапка есть, но невидима.
  • Память. Окно кэша «2 клипа» = до 130 ImageBitmap 1280×720 ≈ 470 МБ. На десктопе терпимо, на слабых ноутбуках — свопы и рывки. Решается переходом на видеоклипы (3.6).
  • Долгая задача при старте (~650 мс main-thread): рендер 70-килобайтного шаблона Home + 7 постеров + 7 стилей + шрифты + инициализация ~40 ScrollTrigger'ов одновременно с 64 fetch кадров интро.

P0#10 · Точки навигации и мини-план приземляются на предыдущую сцену

Файл
js/film.js → onRoomNav, onPlan, onStart
Причина
scrollEl(rooms[idx]) скроллил к верхней кромке комнаты. Для ScrollTrigger start:'top top' это прогресс 0: кадр = prev.f, is-driving, оверлей скрыт; snap [0, .35] держит там. Иногда Lenis останавливался на 0.5 px выше кромки и onEnter не срабатывал вовсе.
Доказательство
до: клик по точке 3 → scene:"2", frame:191, ovShow:false; назад по точке 1 → scene:"1", frame:63, is-driving. После: точка 3 → scene:"3", frame:255, ovShow:true; 1 → 127/true; 6 → 383/true; 0 → 63/true.

P0#9 · Прокрутка вверх: камера не едет, стоит предыдущий кадр

Файл
js/film.js → afterArrive(i)
Причина
После прибытия в комнату грузился только диапазон S[i].f → S[i+1].f. Диапазон назад никогда не запрашивался (а окно памяти его даже «держало»), поэтому при обратном проезде nearest() отдавал ближайший кэшированный кадр — стоп-кадр сцены.
Доказательство
прокрутка вверх из комнаты 3: до — 1 уникальный кадр за проезд; после — 14 (255,251,244,229,216,204,196,192,191,187,173,146,133,127).
/* film.js — Fix #9: прелоад в обе стороны (вперёд приоритетнее); blend-переходы (flash) диапазона не требуют */
function afterArrive(i){if(!alive)return;const nx=S[i+1],pv=S[i-1];const win=[];
  if(pv)win.push([pv.f,S[i].f]);if(nx)win.push([S[i].f,nx.f]);prune(win);
  const fwd=!!(nx&&!nx.flash&&!S[i].flash),bwd=!!(pv&&!pv.flash&&!S[i].flash);
  if(fwd)ensureRangeLow(S[i].f,nx.f);if(bwd)ensureRangeLow(pv.f,S[i].f);
  setTimeout(()=>{if(!alive||cur!==i)return;
    (fwd?ensureRange(S[i].f,nx.f,4):Promise.resolve()).then(()=>{if(alive&&cur===i&&bwd)ensureRange(S[i].f,pv.f,3);});},150);}

P0#1 · Возврат на главную / к верху: пропадают заголовок, подписи, логотип

Файлы
js/film.js (две правки), css/site.css (nav)
Причина 1
У комнаты 0 не было обработчика прибытия. onLeaveBack комнаты 1 ставил is-driving и прятал оверлей, а восстановить сцену 0 было некому. Воспроизведено: скролл вниз до Bad и колёсиком обратно → scene:"1", is-driving, ovShow:false при y=0.
Причина 2
При каждом возврате на Home интро проигрывалось заново: очистка кэша → 64 fetch → ждать до 3 с → 3.4 с клипа. Итого 6–7 с сцены без единого слова.
Причина 3
Nav в состоянии overhero (scrollY ≤ 40) — белая типографика без подложки. Над светлым кадром ванной вордмарка неразличима (ваш 5-й скриншот).
После
верх после прокрутки — scene:"0", ovShow:true; возврат из Leistungen — заголовок виден через 1.6 с (вместо 6–7 с).

P1#3 · Открывающий клип начинается с рывка

Файл
js/film.js → инициализация frame, playIntro(), setupRoom()
Причина
(a) первый нарисованный кадр — 63 (конец клипа), затем прыжок на 0; (b) старт по таймеру 3 с на неполном кэше → nearest() повторяет соседние кадры (замер: 198 мс на кадре 0, 165 мс на кадре 1); (c) 7 стоп-кадров и 64 кадра интро качались одновременно; (d) при скролле во время интро step() и updateRoom() писали в frame одновременно.
После
кадры 0→63 без обратных прыжков; при медленной сети клип пропускается (ваше условие: «лучше без стартовой анимации, чем с лагом»).

3.3 · Motion v8 — «станции» вместо скраба ТЗ

Ваша идея, зафиксированная как модель

Скролл управляет только текстом; камерой управляет система. Пользователь докрутил до сцены — информация уже в кадре и дораскрывается прокруткой; дочитал, крутит дальше — камера сама едет в следующую комнату (1.6–2.2 с), старый текст уходит, новый приходит. Застрять на середине проезда невозможно, потому что середины как состояния больше нет. Это возврат к принципу SPEC-v6 («Kamera fährt selbst»), но с прелоадом и защитами, которых тогда не было.

Модель

Станция i (высота STATION_VH = 1.6 · 100vh, ScrollTrigger start 'top top' end 'bottom top') p ∈ [0, 1] — прогресс чтения. Кадр = S[i].f, стоит. Drift (Ken Burns 1.00→1.04) едет от p. reveal(i,p): кикер+заголовок p≥.05 факт 1 p≥.22 факт 2 p≥.38 факт 3 p≥.54 хотспоты p≥.62 CTA p≥.70 EXIT_AT = .86 — после этого прогресса «всё прочитано» onLeave (p→1, вниз) → drive(i → i+1) onLeaveBack (p→0, вверх) → drive(i → i−1) drive(from, to): state = 'driving' 1. Smooth.stop(); wheel/touch/keys глушатся (passive:false, preventDefault) 2. параллельно: textOut(from) 0 → .30 dur (opacity, y −12px, stagger 40 ms, обратный порядок) frameTween 0 → 1.00 dur (from.f → to.f, power2.inOut; dur = clamp(|Δf|/64 · 1.8, 1.6, 2.2)) textIn(to) .70 → 1.00 dur (кикер+заголовок; факты остаются на скролл) 3. onComplete: Smooth.to(top(to) + (dir>0 ? 2 : h·EXIT_AT − 2), {immediate:true}); Smooth.start(); state='idle' (скролл-позиция и картинка снова согласованы; при движении вверх приземляемся в «прочитанное» состояние)

Требования и граничные условия

  • Ввод во время проезда. Колесо, тач, клавиши — проглатываются; запоминается только знак последнего wheel. Если после проезда знак противоположен направлению — ничего не делаем (пользователь передумал). Если совпадает и |Δ| суммарно > 600 px — не цепляем автоматически следующий проезд: одно действие = один переход. Это защита от «пролетел три комнаты».
  • Точки, мини-план, «Rundgang». Прыжок к станции k: если |k − cur| = 1 — обычный drive. Если больше — один проезд по кадрам напрямую cur.f → k.f с длительностью 2.2 с по low-res-кадрам (они есть всегда, 8 МБ) + подмена на full-res по прибытии. Промежуточные станции не «останавливаются».
  • Кадры не готовы. drive ждёт до 400 мс (rangeReady, сначала low-res). Не дождался — кроссфейд между двумя стоп-кадрами 600 мс. Никогда не показывать «шаг» по 3–4 кадра.
  • Гарантия выхода из состояния. Watchdog: если state==='driving' дольше dur + 1000 мс — принудительно завершить (frame = to.f, Smooth.start()).
  • Deep-link / history. Приземление на станцию без проезда (frame = S[k].f, текст сразу в конечном состоянии).
  • Blend-сцены (Rohbau, кадр = фото): drive = кроссфейд 1.2 с, механика та же.
  • Листы (те, что остаются, см. 3.4): лист — обычная секция после станции; стан­ция i → лист → станция i+1. Выход со станции вниз в лист — не проезд (кадр темнеет через cover()); первый скролл из листа вниз в следующую станцию запускает drive(i → i+1). Т. е. лист всегда «между» и никогда не ломает согласованность кадра.
  • Клавиатура и a11y. ↓/PageDown/Space = «дочитать станцию → следующий проезд», ↑ — симметрично; точки — aria-current. Проезд объявляется через aria-live="polite" текстом кикера. prefers-reduced-motion: проезд заменяется кроссфейдом 300 мс, текст без stagger (текущая продуктовая позиция «анимация всегда» пересматривается только в этой части — это требование WCAG 2.3.3).
  • Телефон (lite) — без изменений: стоп-кадры + затухание; факты становятся обычным текстом под заголовком.

3.4 · Информация внутри сцен, конец «гигантских карточек» ТЗ

Принцип

Правило SPEC-v6 «≤ 3 строки + 1 картинка → в комнату; сетка/форма/калькулятор → лист» так и не было применено: в комнатах по одному заголовку, а листы разрослись до 5–7 экранов. Новое правило: каждая сцена несёт 3 факта из бывшей карточки, листов остаётся три, и они становятся «полулистами» (панель 46 % ширины поверх фильма, кадр остаётся виден слева и темнеет до 35 %). Домашняя страница сокращается примерно с 28 000 до ~16 000 px.

3.6 · Открывающий клип и производительность ТЗ

Патч из раздела 2 закрывает баг. Ниже — как сделать, чтобы интро не приходилось пропускать вообще.

  1. Интро как видео. 64 WebP (2.3 МБ, 64 запроса) → один img/film/intro.webm (VP9, 1280×720, ~350–450 КБ, 8 fps → перекодировать в 24 fps с интерполяцией из исходного клипа C1 в film/src) + intro.mp4 (H.264) для Safari. Проигрывание: скрытый <video muted playsinline preload="auto">, кадры на тот же canvas через drawImage(video) → ни одной строки в остальной механике не меняется; по ended — finish(). Тот же приём применим к 6 проездам в v8 (12 клипов с обратными версиями ≈ 4 МБ вместо 22 МБ кадров, и память ≈ 0).
  2. Очередь загрузки. <link rel="preload" as="video"> для интро; постеры .w-still (7 × 810×1440) — loading="lazy" кроме первого; .w-room img — lazy все; шрифты — font-display: swap уже есть.
  3. Длинная задача при старте (650 мс): content-visibility:auto; contain-intrinsic-size: 1px 1200px на все .w-sheet; marquee-клонирование и worksInit — в requestIdleCallback; ScrollTrigger'ы листов создавать лениво (IntersectionObserver на первый лист).
  4. Preloader: снимать по первому кадру, не по таймеру 1.8 с — уже так, но добавить минимум 400 мс показа, чтобы не мигал.

Приёмка: LCP ≤ 2.0 с на throttled «Fast 3G / CPU ×4», интро стартует без пропуска в 95 % запусков на 10 Мбит/с.
