# BauStern — оптимизация кадрового бюджета, 14 сентября 2026

## Изменения

- `site/js/film.js`: меньше повторных присваиваний стилей и текста; отмена отложенного кадра при демонтаже; камера не реагирует на курсор за закрывающим её контентом. Панель материализации отделена от движущейся камеры. Стрелки ползунка больше не переключают комнату. Нативный scroll-snap не сбрасывает прогресс материализации в зоне просмотра.
- `site/js/film-fx.js`: физика инерции зависит от прошедшего времени, а не от количества кадров; прокрутка отменяет остаточную скорость перетаскивания, чтобы не оставлять бесконечный idle-rAF. Повторные записи одной прозрачности пропускаются.
- `site/css/site.css`: пульсация индикатора обратного звонка переведена с анимации тени на transform/opacity. Скрыт перекрытый материализацией canvas; удалён ненужный отдельный композитный слой. Новая панель ползунка находится под навигацией, не пересекает заголовок и скрывается над контентными листами.
- `site/js/pages.js`: семантика ползунка и доступное значение; исправлено неподтверждённое обещание удаления CRM-заявок через 12 месяцев. Регенерированы 31 маршрут и 404.

Качество исходных изображений не понижалось. Композитные фотографии Rückblende — 1920×1071; проверка в viewport 3840×2160 не превращает исходники в настоящие 4K. Сохранены Archivo / Instrument Sans, светлые панели и текущая палитра. При полировке использованы подходы redesign-existing-projects и accessibility-review: отделение управления от медиа, контраст, фокус, клавиатура и проверка реальной геометрии.

## Почему нельзя дать универсальную гарантию 60 FPS

Стандартный Playwright headless-shell в этой среде использует SwiftShader: программные compositor, rasterization и video decode. Это стресс-профиль CPU, а не работа видеокарты пользователя. Отдельно проверен чистый профиль установленного Google Chrome: NVIDIA GeForce GTX 1080, аппаратное ускорение активно. Записаны оба профиля, их результаты нельзя смешивать.

Время между `requestAnimationFrame` показывает доступность кадрового цикла браузера, но само по себе не доказывает частоту вывода пикселей физического дисплея. Для мобильного видео отдельно собираются `requestVideoFrameCallback` и droppedVideoFrames. Перегрев, энергосбережение, фоновые приложения, декодер и частота дисплея остаются внешними ограничениями.

- Физика при 30/60/120/180 Гц: одинаковый прогресс через 200 мс; движение и остаточная скорость корректно завершаются.
- Панель материализации: Home → 0%, ArrowRight → 5%, End → 100%; мышь, drag, возобновление scroll; 8 конфигураций Chromium/WebKit от 1000×700 до 3840×2160. Проверены отсутствие пересечений и переход desktop → mobile.
- Axe для новой панели: 13 пройденных правил, 0 нарушений. Автоматическая оценка контраста над фотографией была неоднозначна; расчёт по computed styles и худшему фону: текст 6,68:1, стрелки 6,85:1.
- Desktop: 98 проверок сцен/возврата в Chromium и 98 в WebKit, 7 размеров; ошибки и геометрические нарушения не обнаружены.
- Мобильная маршрутная матрица: 279 проверок в Chromium и 279 в WebKit — 31 маршрут × 9 размеров (320–812 px, включая landscape); 0 нарушений геометрии и 0 недостаточных тач-зон в проверяемом наборе.
- Мобильный кино-тур: 63 сцены и 4 резервных режима в каждом движке, суммарно 126 сцен и 8 fallback-проверок. Проверены подсказки, пауза, обратный переход, демонтаж и повторный вход, reduced motion, Save-Data, недоступное видео и запрет autoplay.
- Формы: 69 проверок в каждом движке, 138 суммарно; все отправки имитированы, реальных новых заявок нет.
- Исходный протокол: jsdom-smoke / route / flight / hybrid / sig / final-home / crawl — exit 0. Логика jsdom-smoke не изменялась. В route-test есть ожидаемый HTTP 404 для специально несуществующего адреса; это не неожиданный сбой ресурса.
- Сборка: 11 JS, 4 CSS, 31 маршрут, без ошибок.
- Mobile bench 375/393/430: p95 rAF 16,7 мс, CLS 0, touch-scroll проходит. Видео реально доставляло примерно 59,4–60 кадров/с; отдельные стартовые пропуски зафиксированы, а не скрыты.

Полные журналы находятся в `core/dev/reports/frame-budget-2026-09-14/`; матрицы — `core/dev/reports/frame-budget-mobile-*`, desktop — `core/dev/reports/desktop-polish-frame-budget-final-*`.

### Исправление нестабильного ожидания в тесте

Первый завершающий прогон WebKit остановился на запуске видео сцены 1: старый тест требовал `currentTime > 0` уже через фиксированные 350 мс. При повторной диагностике воспроизведение действительно запускалось позже. В `mobile-cinema-test.js` заменено ожидание по таймеру на фактическую готовность воспроизведения с ограничением 3 секунды; продолжительность старта теперь сохраняется в отчёте. Проверки кадров, текста, подсказок и ошибок не отключались. Полный повторный WebKit-прогон прошёл; наблюдавшееся время от команды tap до подтверждённого воспроизведения — 543–1457 мс, включая время автоматизации. Это исправление синхронизации теста, не доказательство мгновенного старта видео на всех устройствах.

## Финальные замеры производительности

`final-acceptance.json`: отдельный прогон установленного Chrome с аппаратным compositor на NVIDIA GTX 1080, без параллельных браузерных тестов. Во всех 12 движущихся сценариях p95 ниже регрессионного порога 16,8 мс; ошибок и нарушений геометрии нет.

| Viewport | p95 прокрутки | p95 материализации туда / обратно | p95 движения курсора в ванной | Лишние drawImage в покое за 1 с |
|---|---:|---:|---:|---:|
| 1440×900 | 11,2 мс | 5,6 / 5,6 мс | 5,6 мс | 0 |
| 1920×1080 | 11,2 мс | 5,6 / 5,6 мс | 5,6 мс | 0 |
| 3840×2160 | 5,7 мс | 5,6 / 5,6 мс | 5,6 мс | 0 |

При материализации и движении курсора доля интервалов rAF >33,4 мс — 0% во всех размерах. При прокрутке — 1,74% / 0,32% / 0,10% соответственно. То есть отдельные задержки существуют: результат **не означает, что абсолютно каждый кадр был быстрее 16,7 мс**. Высокочастотный кадровый цикл браузера и вывод пикселей дисплея — разные измерения.

`diagnostic-software-final.json`: два отдельных повтора с полным интерфейсом на программном SwiftShader — медиана 16,7 мс, p95 33,4 мс; интервалы >33 мс составили 33,09% и 25,00%. До изменений сопоставимый диагностический baseline давал около 50,2%; число Layout уменьшилось примерно с 251 до 98 за сценарий. Это наблюдение на стенде, а не гарантированное ускорение для каждого устройства. Программный путь всё ещё **не проходит строгий 60-Hz бюджет по p95**. Диагностическое скрытие интерфейса не использовано как production-результат.

Мобильные результаты приведены выше отдельно. Физическая проверка iPhone/Android и полевая статистика Core Web Vitals не заменяются этими замерами rAF.

```powershell
npm run build
node frame-physics-test.js
node material-controls-test.js
node slider-accessibility-test.js

```

Тесты производительности запускать отдельно от остальных браузерных прогонов. У `frame-budget-acceptance.js` доступны `BASE` и `TAG`; по умолчанию используется localhost:8098 и установленный Chrome с аппаратным ускорением. Не интерпретировать его результат как физическую сертификацию iOS/Android.
